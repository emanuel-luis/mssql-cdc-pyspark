# CLAUDE.md

Guidance for Claude Code when working in this repository.

`mssql-cdc-pyspark` is a platform-agnostic **PySpark DataSource V2 streaming source
for SQL Server CDC**, plus a Delta sink and a **completeness signal**
(`finalized_until`) for downstream consumers. See `README.md` for the product, the
documentation site (`docs/`, built by Zensical from `mkdocs.yml`, ADR 0024) for usage,
`docs/ARCHITECTURE.md` for how it works, `docs/DESIGN.md` for why.

## Commands

Per-platform setup (Linux, Windows with WSL2, Windows native) is in
`docs/DEVELOPMENT.md`. Native Windows also needs `HADOOP_HOME` (winutils) and
`PYSPARK_PYTHON` pointing at the venv interpreter.

```bash
uv sync                                             # .venv + dev group (pytest, Spark, Delta, Faker, mssql-python)
. .venv/bin/activate                                # or prefix every command with `uv run`

pytest -q                                           # unit tests, no SQL Server needed
MSSQL_CDC_TEST_DELTA=0 pytest -q                    # skip trying to resolve Delta jars (faster)
pytest tests/test_source_fake.py::test_idle_dummy_entries_advance_offset_and_finalization

cp .env.example .env                                # then set MSSQL_SA_PASSWORD in .env (left empty)
docker compose up -d                                # SQL Server 2022 + Agent
python -m lab.workload setup                        # db, tables, CDC
python -m lab.workload seed | stream | bulk | long-tx
python -m lab.checks.t5_engine                      # t1..t10, see LAB.md
python examples/local_pipeline.py

uv run ruff check                                   # lint (add --fix for the safe fixes)
uv run ruff format                                  # format (CI runs --check)
uv run mypy                                         # strict: src/ and tests/typing_*.py
uv run pyright --verifytypes mssql_cdc --ignoreexternal  # public API 100% typed (ADR 0031)
```

`make` targets mirror these on Linux; `scripts/lab.ps1` is the PowerShell
equivalent.

## Invariants (do not break without an ADR)

1. **Offset contract.** `{"lsn": "0x" + 20 uppercase hex, "commit_ts": "<UTC ISO-8601, ms>"}`.
   It lives in users' checkpoints: renaming keys or changing formats breaks resumes.
   `lsn` is the last *processed* commit LSN.
2. **Batches are commit-history prefixes.** A batch reads the closed interval
   `[fn_cdc_increment_lsn(start), end]` of the change table `cdc.<ci>_CT` (not
   `fn_cdc_get_all_changes_*`, ADR 0009) with `end <= sys.fn_cdc_get_max_lsn()`, and ends
   on a commit boundary (`maxCommitsPerBatch` counts `cdc.lsn_time_mapping` rows). When the
   table has a newer capture instance, the interval is cut at its `start_lsn` S: the older
   instance's change table below S, the newer one's from S, each range naming its own
   (ADR 0023).
3. **No empty ranges.** `partitions()` returns `[]` when `end <= start`; never plan a
   range with `from > to`.
4. **Retention guard, twice.** On the driver, if `increment(start) < fn_cdc_get_min_lsn(ci)`;
   on the executor, after reading a range, if `fn_cdc_get_min_lsn(ci)` moved past its
   `from_lsn` (cleanup ran meanwhile; the change table does not fail on purged ranges).
   Raise `DataLossError` unless `failOnDataLoss=false`. Silent skipping is data loss: the
   driver's skip leaves a `'data_skipped'` facts row with the gap (`certain` true in
   `detail`), and so does the executor's, through its metrics file, as a possible loss
   (`certain` false) (ADR 0018).
   A third check, `to_delta(on_data_loss="resnapshot")`'s pre-flight, applies the driver's
   test before the query starts and re-snapshots into a new generation instead (ADR 0018).
   With two capture instances, `ci` is the instance the range reads; the pre-flight uses the
   one the next changes are read from (ADR 0023).
5. **Executors are stateless.** `read()` opens and closes its own connection; the
   reader drops `_client` in `__getstate__`. Nothing live gets pickled.
6. **LSNs cross every boundary as hex strings.** Bound as `CONVERT(binary(10), ?, 1)`,
   returned as `CONVERT(varchar(22), <lsn>, 1)`. That is what keeps backends
   interchangeable; do not bind or decode binary in Python.
7. **Every Arrow batch is cast to the declared Spark schema** before it is yielded.
8. **Sink idempotency.** `app_id` is stable for a checkpoint's lifetime; a new
   checkpoint needs a new `app_id` (batch ids restart at 0). A re-snapshot generation `n`
   gets both: `<checkpoint>/_generations/<n>` and `<app_id>.g<n>` (ADR 0018).
9. **Finalization ordering.** Data committed first, `finalized_until` advanced after,
   monotonic (`GREATEST` semantics). Never store it in `TBLPROPERTIES`.
10. **Platform-agnostic core.** Nothing under `src/mssql_cdc` imports `dbutils`,
    `databricks.*` or other platform APIs. Platform glue belongs in `examples/` and docs.
11. **Least privilege.** Beyond what the CDC query functions need, the reader needs only
    `SELECT` on `cdc.<ci>_CT` of each capture instance it reads (ADR 0009). Metadata comes
    from documented APIs (`sys.sp_cdc_get_captured_columns`,
    `sys.sp_cdc_help_change_data_capture`, `sys.sp_cdc_get_ddl_history`, `sys.fn_cdc_*`),
    plus `sys.columns` of the source table (a snapshot's columns, computed columns); do
    not add reads of other `cdc.*` tables except `cdc.lsn_time_mapping`, which needs no
    grant. The library never creates or drops capture instances.
12. **Snapshot LSN first.** A snapshot's LSN S is the `max_lsn` recorded *before* any of its
    rows is read, and a rerun returns the S of the snapshot already written (or, chunked,
    opened), never a newer one (ADR 0016). A chunked snapshot's rows are stamped per wave with
    a `max_lsn` recorded before that wave's read: a lower bound of what the row reflects,
    always >= S (ADR 0028). Snapshot rows are `_operation = 0` with `_snapshot` = S; a
    snapshot is identified by `coalesce(_snapshot, _start_lsn)` and its completion event,
    never by the largest `_start_lsn` of its rows. Never read with `NOLOCK`. A chunked
    snapshot's chunks are planned once, by the first `backfill()`, into its `'snapshot_plan'`
    facts row, and never change while it is open; they tile the key space up to just above
    the MAX recorded at the open. A run takes its snapshots in one mode, and a snapshot open
    in one mode blocks the other (and `seed()`) until its completion row (ADR 0028).
13. **SQL injection.** Anything inlined into T-SQL (capture instance, columns, timezone,
    integers) goes through the validators in `client/_validators.py`.
14. **Schema changes are checked before the read.** DDL inside a batch's range is found on
    the driver while planning; a captured type the query's no longer holds fails the batch
    before any row is read (`SchemaChangedError`; with `columns`, only a change made while
    the query runs). An instance's columns are checked the first time a run reads it; a
    source column no instance captures fails instead of reading NULL. Computed columns
    (`sys.columns.is_computed`; CDC stores NULL in every change row) are left out of the
    inferred schema, and one listed in `columns` reads NULL in snapshot rows too (ADR 0007).
    A snapshot matches captured and source columns by `column_id`, never by name alone (a column dropped and
    added back is another).
    `_command_id` is per capture instance: order across instances by
    `(_start_lsn, _seqval, _operation)`. Only `'bootstrap'` and `'resnapshot'` facts events
    are snapshots (ADR 0023): `'snapshot_open'` (written by both modes), `'snapshot_plan'` and
    `'snapshot_chunk'` rows are not, and a chunked snapshot's completion row (min = max = S)
    comes after its last chunk (ADR 0028).

## Testing strategy

* `tests/test_source_fake.py` runs the real streaming engine in local mode against
  `FakeCdcDatabase`: add a test there for any change to offsets, batching, guards or
  output schema. The fake must keep matching real CDC semantics (see `docs/DESIGN.md`);
  when a lab check reveals a difference, fix the fake too.
* `tests/test_client_sql.py` pins the T-SQL shape.
* `tests/test_properties.py` checks invariants over Hypothesis-generated inputs (LSN math,
  chunk plan tiling, silver's latest image, boolean options), derandomized and capped; all
  but the silver one start no JVM. A new invariant of pure logic gets a property there; prove it fails by
  breaking the code it guards once.
* `tests/integration` runs the source against a throwaway SQL Server 2022 (testcontainers,
  server clock in `America/Sao_Paulo`). `uv run pytest -m sqlserver`; needs Docker. The
  default run deselects it. Add a test there for anything that depends on how SQL Server
  or the driver actually behaves.
* `tests/compat/test_compat.py` resumes the state each released wheel wrote
  (`tests/compat/<version>`) with the current code: a change that fails it breaks the
  state contract (ADR 0021).
* `lab/checks` prove SQL Server behaviour; CI (`.github/workflows/ci.yml`) runs them
  against `mcr.microsoft.com/mssql/server:2022-latest`.
* Claims in docs or write-ups must be backed by a check result in `lab/results/` or a
  passing test in `tests/integration`. The one exception is a measurement taken outside
  the repo against a real source (throughput over a real link, for instance): state it as
  such ("measured against a production source", with the setup), never with names of the
  source, its tables or its owner.

## Settled by the lab

Delta (t6, CI and DBR 18.2): `userMetadata` set through the session conf reaches MERGE
commits, and the session txn confs make a replayed MERGE a no-op.

Settled by `tests/integration` and t3: `fn_cdc_get_all_changes_*` does not return
`__$command_id` on SQL Server 2022, the change table does (ADR 0009); `mssql-python`
binds `CONVERT(binary(10), ?, 1)` parameters; every type in the inferred-schema mapping round-trips through Arrow into
its default Spark type; `tran_end_time` follows the server's local clock and
`sourceTimeZone=auto` converts it to UTC. Under locking READ COMMITTED a chunk read waits
(`LCK_M_S`) for a transaction holding locks in its range; SNAPSHOT isolation is refused until
`ALLOW_SNAPSHOT_ISOLATION` is on; `sys.sp_spaceused` answers a login with only column grants.
The drivers return `datetime2(7)` truncated to the microsecond, chunk bounds included, so a
keyset plan's last chunk is open when the key after MAX shares MAX's microsecond.
Idle entries in `cdc.lsn_time_mapping` come
about every 5 minutes (t1); `sql/heartbeat.sql` brings `max_lsn`'s lag to ~10 s
(`tests/integration`, ADR 0010).

## Conventions

* English in code, docs, commit messages. Python ≥ 3.10, type hints, small modules.
* CI's `lint` job runs `ruff check`, `ruff format --check`, `mypy` (strict, on `src` and
  `tests/typing_*.py`; config in `pyproject.toml`) and `pyright --verifytypes mssql_cdc
  --ignoreexternal` (fails below 100%: annotate a public constant or attribute whose type is
  inferred), and gates every other job: run them before pushing (ADR 0031). A broad
  `except` says why: `# noqa: BLE001 - <reason>`.
* PySpark is an optional extra (`[spark]`) because platforms ship their own: installing
  PyPI `pyspark` on Databricks, EMR, Dataproc or Fabric, or next to Databricks Connect,
  conflicts with the platform's Spark (DBR 18.2 is Spark 4.1). Do not add hard dependencies
  to `[project].dependencies` beyond `pyarrow` and `mssql-python` (the default backend,
  ADR 0003).
* Usage is documented once, on the site: keep `docs/reference/options.md` and
  `docs/reference/output-schema.md` in sync with the options read in `src/mssql_cdc/source.py`,
  `client.make_client` and `pipeline.to_delta`; `docs/reference/tables.md` copies the table
  comments, which `tests/test_docs_tables.py` checks. A new page needs a line in
  `mkdocs.yml`'s nav; `uv run --group docs zensical build --strict` must pass (CI `docs` job).
* Changing the control, facts, bronze or silver schema: update its creation columns *and* append a
  migration to `src/mssql_cdc/migrations/<kind>.py` (ADR 0013); never edit a shipped one.
* Releasing follows `docs/RELEASING.md`: once a final release is on PyPI, generate
  `tests/compat/<version>` from its wheel with `tests/compat/generate.py` and commit it
  (a release candidate gets none).
* Record design changes as a new ADR in `docs/decisions/`, with `**Date:**` (ISO-8601 with
  the UTC offset) and an `**Amended:**` line per later change (see `docs/decisions/README.md`).
